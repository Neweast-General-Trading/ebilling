# eBilling — دليل المستخدم (Business)

> **NEWEAST · Etisalat SIM Billing**  
> دليل مبسّط لموظفي HR والFinance — بدون تفاصيل تقنية

---

## 1. شو هو eBilling؟

**eBilling** نظام داخلي لإدارة فواتير **خطوط e& (Etisalat)** للموظفين.

**باختصار:**
- HR ترفع فاتورة PDF
- النظام يقارنها مع **باقة الموظف** المسموحة
- إذا الفاتورة **أعلى من الباقة** → الموظف يوافق: شو **رسمي (شركة)** وشو **شخصي**
- الجزء **الشخصي** يُرحَّل لاحقاً لـ **Oracle** (خصم من الراتب)

**الرابط:** [ebilling.neweast.cloud/ebilling](https://ebilling.neweast.cloud/ebilling)

## 2. مين بيستخدم النظام؟

| الدور | شو بيعمل |
|-------|----------|
| **HR / Finance** | رفع الفواتير، متابعة الموافقات، ترحيل Recovery |
| **الموظف** | يستلم إيميل → يفتح رابط → يوافق ويقسّم المبلغ |
| **Super Admin** | إدارة الصلاحيات + لوحة E-bill Approval |

---

## 3. المصطلحات المهمة (بلغة بسيطة)

| المصطلح | المعنى |
|---------|--------|
| **Package** | المبلغ المسموح شهرياً للموظف (حسب SIM Master) |
| **Invoice Total** | المبلغ الكامل في فاتورة e& |
| **Exceeded / Excess** | الفرق: الفاتورة − الباقة (إذا طلعت أعلى) |
| **Official** | جزء من التجاوز **للعمل** — على الشركة |
| **Personal** | جزء من التجاوز **الشخصي** — يُخصم من الموظف |
| **Recovery** | إرسال المبلغ الشخصي إلى Oracle للخصم |
| **SAP Code** | رقم الموظف في Oracle — لازم يكون مربوط بالخط |

**قاعدة ذهبية:**  
Official + Personal = Exceeded Amount (لازم يكونوا متساويين مع التجاوز)

## 4. الرحلة الكاملة — خطوة بخطوة

### الخطوة 1: HR ترفع الفاتورة

**من:** Invoices → رفع PDF (واحد أو folder كامل)

**النظام تلقائياً:**
- يقرأ الرقم والمبلغ والشهر
- يربط الفاتورة بالموظف من **Master**

**ثلاث حالات ممكنة:**

| الحالة | شو يصير |
|--------|---------|
| الرقم **مو موجود** في Master | يطلب من HR تسجيله أولاً |
| الفاتورة **ضمن الباقة** | تأكيد تلقائي + إيمail للموظف — **خلص** |
| الفاتورة **فوق الباقة** | → الخطوة 2 |

---

### الخطوة 2: ماذا يحدث عند وجود تجاوز؟

#### أ) الموظف **مربوط بـ SAP** (الحالة العادية)

1. النظام يرسل **إيمail للموظف** مع رابط موافقة
2. الفاتورة تظهر في **Pending Approval** (لوحة يمين)
3. الموظف يفتح الرابط ويقسّم: Official / Personal
4. بعد الموافقة → تنتقل لـ **Ready for Recovery**

#### ب) الموظف **ما مربوط بـ SAP**

- النظام **ما يرسل** إيمail موافقة
- الفاتورة تروح **مباشرة** على **Ready for Recovery**
- كل التجاوز يُعتبر Personal (ما لم يُعدَّل لاحقاً)

> **نصيحة:** تأكد من SAP Code في Master قبل رفع الفواتير لتجنب تخطي موافقة الموظف.

---

### الخطوة 3: الموظف يوافق (من الإيمail)

**الموظف يفتح الرابط** (بدون login للنظام):

1. يشوف ملخص الفاتورة والتجاوز
2. يقسّم المبلغ:
   - **Official** = استخدام عمل
   - **Personal** = استخدام خاص (يُخصم)
3. يكتب **Remarks** (اختياري) — ملاحظات للـ HR
4. يضغط **Submit**

**بعد الموافقة:**
- الموظف يستلم إيمail تأكيد
- HR تشوف التحديث في الجدول ولوحة الموافقات

---

### الخطوة 4: HR تراجع وترحّل (Recovery)

**من لوحة E-bill Approval (يمين الشاشة):**

| القسم | ماذا يحتوي |
|-------|------------|
| **Pending Approval** | فواتير بانتظار رد الموظف |
| **Ready for Recovery** | فواتير موافق عليها — جاهزة Oracle |

**أزرار HR:**
- **Open** — فتح تفاصيل / رابط الموظف
- **Resend** — إعادة إرسال الإيمail (إذا الموظف ما رد)
- **Recovery** — ترحيل المبلغ الشخصي لـ Oracle

> **Recovery** يشتغل فقط إذا: SAP موجود + Personal > 0 + الموظف وافق

## 5. حالات الفاتورة — ماذا تعني؟

| الحالة في الجدول | المعنى | ماذا تفعل |
|------------------|--------|-----------|
| **Confirmed** | بدون تجاوز أو personal = 0 | لا شيء — مغلقة |
| **Pending approval** | بانتظار الموظف | انتظر أو Resend |
| **Waiting confirmation (2)** | أُرسل إيمail مرة ثانية — الرقم = عدد الإرسالات | انتظر رد الموظف |
| **Ready for recovery** | جاهزة Oracle | اضغط Recovery |
| **Recovery sent** | تم الترحيل | للمراجعة فقط |

## 9. SIM Master — ليش مهم؟

**Master** = سجل خطوط الموظفين.

**لازم يكون صح:**
- رقم الخط
- Email الموظف
- Package / Total amount
- **SAP person number** (للـ Recovery)

**إذا ناقص:**
- Email ناقص → ما ينرسل إيمail موافقة
- SAP ناقص → تخطي موافقة الموظف → Ready for Recovery مباشرة
- Package غلط → Excess غلط

---

## 10. الصلاحيات (Permissions)

**Super Admin** يقدر:
- يضيف مستخدمين من **Oracle (SIM employees)**
- يضيف **External email** — أي إيمail عمل بدون Oracle
- يحدد أي تبويبات يشوفها: Dashboard, Invoices, Master, Analysis, Recovery, Users Log

**مستخدم عادي:** يشوف فقط التبويبات اللي ممنوحة له.

---

## 11. أسئلة شائعة

### الموظف ما استلم إيمail؟
1. تأكد Email صحيح في Master
2. Resend من لوحة Pending Approval
3. تحقق Spam — CC يروح لـ end.bill

### الموظف وافق بس Remarks ما ظهرت؟
- HR تقدر تضيف HR remark يدوياً
- أو الموظف يفتح الرابط مرة ثانية (إذا ما كان عنده remarks) ويحفظ

### Recovery فشل؟
- تأكد SAP Code صحيح
- تأكد Personal > 0
- راجع رسالة الخطأ في Recovery log

### فاتورة برقم مش معروف؟
- سجّل الخط في Master أولاً
- أو اربط الرفع Pending بالموظف الصحيح

### بدون تجاوز — ليش أُرسل إيمail؟
- إيمail **تأكيد فقط** — ما في مطلوب موافقة

## 12. ملخص سريع — Flowchart

```
HR ترفع PDF
      │
      ├── رقم مش معروف → سجّل في Master
      │
      ├── بدون تجاوز → تأكيد + إيمail → END
      │
      └── في تجاوز
              │
              ├── بدون SAP → Ready for Recovery → HR: Recovery
              │
              └── مع SAP → إيمail للموظف
                              │
                              ▼
                    الموظف يقسّم Official / Personal
                              │
                              ▼
                    Ready for Recovery
                              │
                              ▼
                    HR: Recovery → Oracle → END
```
